# Quest 23: The Spec Room

> **このクエストのねらい**
>
> 仕様書（spec）を読みます。MUST・MUST NOT・SHOULD・MAY の強さの違いを知り、実装やデータが仕様を守っているかを確かめます。SHOULD を守っていないだけなら「違反」ではないことも経験します。最後は仕様どおりのファイルを自分で作ります。

リリースが終わったばかりなのに、チームの話題はもう **v3** だ。

Haruto が、1つのファイルを共有した。**仕様書（spec）**。ランチアプリがキッチンに送るファイルの形式を決めたものだ。

「このファイルは、いろんなアプリが読むことになる。だから全員が、まったく同じ形で書かないといけない。そのための仕様書だ」

続けて、3つのファイルが届く。

「Daiki、Kaito、Haruka が、それぞれ書き出し（exporter）の案を作ってくれた。仕様に合ってるか、確かめてくれないか」

このクエストで読むのは **仕様書**（英語）です。

## 進め方

`SPEC.md` を読みます。3つの案を実行し、書き出された内容を仕様書と比べます。

    python plan_daiki.py
    python plan_kaito.py
    python plan_haruka.py

ステージ3では、自分でファイルを書いて、チェックします。

    python validate.py my-orders.nox

それから、ステージに答えます。

    python quest.py --stage 1
    python quest.py --stage 2
    python quest.py --stage 3

## ファイル

| ファイル | 中身 |
| --- | --- |
| `SPEC.md` | NOX 1.0 の仕様書 |
| `plan_daiki.py`、`plan_kaito.py`、`plan_haruka.py` | 書き出しの3つの案（ステージ1） |
| `sample.nox` | 古いシステムのファイル（ステージ2） |
| `validate.py` | あなた自身のファイル `my-orders.nox` をチェックする（ステージ3） |

これらのファイルは編集しないでください。ステージ3では、新しいファイル `my-orders.nox` を作ります。

## 言葉の強さ（RFC 2119）

| キーワード | 意味 | 従わないと… |
| --- | --- | --- |
| **MUST** | 必須 | 仕様違反 |
| **MUST NOT** | 禁止 | 仕様違反 |
| **SHOULD** | 推奨。従わないのに十分な理由がある場合もある | 違反では**ない**。ただしよく考えること |
| **SHOULD NOT** | 非推奨 | 違反では**ない** |
| **MAY** | してもよい | 何もない。自分で選んでよい |

ですから、案を確かめるときは、まず **MUST** と **MUST NOT** を探します。

## 確かめ方

1. 決まりを1つずつ読み、短いリストにする
2. 出力（またはファイル）の1行1行を、すべての決まりと照らし合わせる
3. 決まりに範囲があるときは、その両端の値と、すぐ外側の値も確かめる

## 困ったとき

**`validate.py` が「このツールがチェックするのは、あなた自身のファイル … だけです」と言う**

そのとおりです。ステージ1・2は、自分で仕様書を読んで確かめましょう。
