> **このクエストのねらい**
>
> Pull Request（PR）の説明文と差分（diff）を読み比べます。説明文に書いてあることが本当に diff にあるかを確かめ、`-` と `+` を読み分けます。最後は、複数のコミットから、バグを入れたコミットを差分で見つけます。

そして、**Pull Request #57** が出た。

リーダーのコードを、新人がチェックする。少し緊張する。

このクエストで読むのは **プルリクエスト（PR）**（英語）です。説明文、diff（差分）、コミットを読みます。

## プルリクエストの説明文の読み方

説明文には、たいてい次の部分があります。

| 部分 | わかること |
| --- | --- |
| Title | 変更を1行で。`feat: add pre-orders` のような形 |
| Summary | なぜこの変更が必要か |
| `Closes #48` | PR がマージされると、Issue #48 が閉じる |
| Changes | 何が変わったか。ファイルごとに |
| How to test | レビューする人が、変更を試す方法 |

説明文は人が書いたものです。人は書き忘れをします。
ですから、レビューする人は必ず確かめます。**説明文に書いてあることは、本当に全部 diff にあるか？**

## diff の読み方

    diff --git a/settings.py b/settings.py       <- ファイル
    @@ -1,4 +1,5 @@                                <- ファイルの中の場所
     """Settings."""                             <- （空白）変わっていない行
    -PICKUP_TIME = "10:00"                        <- （-）変更前の行
    +PICKUP_TIME = "10:15"                        <- （+）変更後の行

- `-` で始まる行は**消された**行、`+` で始まる行は**加えられた**行です
- 空白で始まる行は**変わっていない**行です。場所がわかるように見せているだけです
- 変更された行は2回出てきます。先に `-`（古い行）、次に `+`（新しい行）です

## バグを入れたコミットを探す（ステージ3）

PR #57 は、あなたのレビューの後でマージされました。その数日後、Kaito から「30件目の予約が断られる」という報告が届きます。
マージの後にも、いろいろな人が `main` にコミットしています。何かが壊れたら、壊したコミットを探します。
`history` フォルダは、マージした後の `main` の履歴を再現したものです（コードは短くしてあります）。

    cd history
    git log --oneline       # コミットの一覧（新しい順）
    git log -p              # すべてのコミットと、その diff
    git show <commit>       # 1つのコミットと、その diff

コミットメッセージは、人が書いたものです。変更の中身を、いつも正しく表しているとは限りません。

わからなくなったら、もう一度 `python history.py --setup` を実行してください。最初の状態から作り直します。
