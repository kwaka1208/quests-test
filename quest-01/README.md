# Quest 1: The Broken Build

> **このクエストのねらい**
>
> Python の Traceback を下から読んで、エラーの種類と原因の場所を突き止めます。JSON のエラーでは、エラーが指す行と本当の原因の行が違うことを経験します。最後は git のマージ衝突を、表示される案内文を読んで解消します。

出社2日目の朝。チームリーダーの Haruto が、モニターの前で頭を抱えていた。

「また止まった……。ビルドするたびに、長いメッセージを吐いて終わるんだよ」

のぞきこむと、画面は英語でびっしり。正直、目がすべる。

そこへ、初日に迎えてくれた先輩エンジニアの Misaki がやってきた。

「ちょうどいい。そのメッセージ、読んで直してみない？」

——え、自分が？

このクエストで読むのは **エラーメッセージ**（英語）です。

エラーメッセージは壁ではありません。どこを見ればよいかを教えてくれる地図です。

## 進め方

ビルドを動かします。

    python build.py

それから、ステージに答えます。

    python quest.py --stage 1
    python quest.py --stage 2
    python quest.py --stage 3

`build.py` は何回動かしてもかまいません。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `build.py` | アプリをビルドする |
| `settings.json` | アプリの設定 |
| `package.json` | パッケージの情報 |
| `checklist.py` | リリースのチェックリストを作り、確かめる（ステージ3） |

`settings.json` と `package.json` は編集してかまいません。このフォルダに新しいファイルを作ってもかまいません。
`build.py` は編集しないでください。コードは壊れていません。

## Traceback の読み方

Python がエラーで止まると、**Traceback** を表示します。

    Traceback (most recent call last):
      File "start.py", line 3, in <module>
        main()
        ~~~~^^
      File "start.py", line 2, in main
        open_door()
        ^^^^^^^^^
    NameError: name 'open_door' is not defined

- "most recent call last" は「最後の呼び出しがいちばん後」という意味です。いちばん新しい手順は**下**にあります
- **最後の行**に、エラーの名前と短い説明があります
- その上の行は、そこにたどり着くまでの道すじです
- `~~~~^^` や `^^^^` の行は、その上のコードのどこが関係しているかを示す印です（Python 3.11 から）
- Python 自身のファイル（たとえば `json/decoder.py`）を指す行もあります。問題はたいていそこにはありません。このフォルダのファイルを探しましょう

つまり、Traceback は**下から上へ**読みます。

## ステージ1：見つからないもの

ビルドが探しているのに、見つからないものがあります。Traceback を読んで突き止めましょう。

ステージ1に答えたら、`settings.json` にそれを足してビルドを続けます。値は何でもかまいません（たとえば `"1.0"`）。JSON の書き方は、ファイルのほかの行をまねしましょう。

## ステージ2：壊れた JSON ファイル

JSON ファイルには厳しい決まりがあります。記号が1つちがうだけで、全部が止まります。
エラーメッセージは、行（line）と列（column）を示します。

    json.decoder.JSONDecodeError: Expecting ':' delimiter: line 3 column 10

ただし、これは Python が問題に**気づいた**場所です。本当のまちがいがある場所とは、ちがうことがあります。

## チェックリスト（ステージ3）

Northwind は、リリースのチェックリストを小さな git リポジトリで管理しています。
Misaki と Haruto が、同じ場所に同時に手順を書き足しました。
どちらの手順も正しいので、チェックリストには**両方**が必要です。

チェックリストを作ります。

    python checklist.py --setup

`checklist` フォルダに移動して、git でマージを最後まで終わらせてください。
何をすればよいかは git が（英語で）教えてくれます。git のメッセージをよく読みましょう。

終わったと思ったら、このフォルダに戻って、チェックリストを確かめます。

    python checklist.py

わからなくなったら、もう一度 `python checklist.py --setup` を実行してください。最初の状態から作り直します。

## 困ったとき

**直したのに、まだビルドが止まる**

それで正常です。新しいエラーメッセージを読みましょう。別のエラーになっているかもしれません。

**`git commit` で見慣れない画面が開いた**

git が、コミットメッセージを書くためのエディタを開いています。行の先頭に `~` がたくさん並んでいたら、それは Vim です。`:wq` と入力して Enter を押すと、保存して閉じます。
次からは、メッセージをコマンドで渡せます。

    git commit -m "Merge the version step"
