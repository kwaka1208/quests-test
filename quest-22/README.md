# Quest 22: The Devlog

> **このクエストのねらい**
>
> 技術記事（devlog）を英語で書きます。冒頭の TL;DR、見出し、100〜300語の本文に、because を使った判断の理由と、選ばなかった案を書きます。

「ポイントの修正、よかったよ」

廊下で、Haruto に呼び止められた。

「あの話、devlog に書いてくれない？ 報告書じゃなくて、物語として。何が問題で、何を試して、何を選んだのか。そして、**なぜ**そうしたのか」

自分の仕事が、誰かの読みものになる。

「ほかのチームの参考になるし、書くと自分の頭も整理されるから」

前のクエストでは devlog を**読み**ました。このクエストでは、devlog を英語で**書き**ます。

## 進め方

`notes.md` のメモを読みます。`devlog.md` に devlog を書いたら、チェックします。

    python check.py --stage 1

ステージの課題に合格すると、チェッカーが単語を1つ表示します。その単語で、同じステージに答えます。

    python quest.py --stage 1

ステージは2つあります。順番に進めてください。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `notes.md` | ポイントの修正についての、あなたのメモ |
| `devlog.md` | あなたの devlog。**このファイルを編集します** |
| `check.py` | devlog をチェックし、単語を表示する |

## devlog の書き方

    # Devlog: How I solved the points mystery

    TL;DR: The whole story in one or two short sentences.

    ## The problem
    ...
    ## What I did
    ...
    ## What's next
    ...

- **TL;DR** を最初に。この1行しか読まない人もたくさんいます
- **物語にする**：問題 → 試したこと → 選んだこと → 学んだこと
- **判断の理由**を `because` で説明する。選ば**なかった**ものを、`but` や `however` で書く
- プルリクエストや Issue に `#58` のように**リンク**する
- **文は短く**。20語以下がちょうどよい長さです
- 先生ではなく、クラスメイトに向けて書く

使える文の形です。

| 言いたいこと | 例 |
| --- | --- |
| 判断 | `I chose ... because ...` |
| 選ばなかった選択肢 | `... was simple, but ...` / `However, ...` |
| 学んだこと | `I learned that ...` |
| 気持ち | `That made me happy.` / `I was surprised.` |
| これから | `Next, I want to ...` |

## ステージ1：形

タイトル、TL;DR（40語以内）、2つ以上の見出しを書き、全体を100〜300語にします。
メモを使いますが、ちゃんとした文で書きましょう。

    python check.py --stage 1

## ステージ2：理由

判断の理由を `because` で説明します。選ばなかった選択肢と比べます（`but`、`however`、`trade-off`）。
修正のプルリクエスト（`#58`）にリンクします。文は短くしましょう。

    python check.py --stage 2

## 困ったとき

**「記事は … 語です」と出る**

コードブロックと `inline code` は数えません。文を足すか、削りましょう。

**「文の長さが平均 … 語です」と出る**

長い文を2つに分けましょう。"and" でつなぐ代わりに、ピリオドで切ります。
