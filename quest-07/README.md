# Quest 7: The Support Desk

> **このクエストのねらい**
>
> 長い Issue のスレッドから、メンテナの発言をもとに結論（修正が入る版と回避策）を見抜きます。途中の間違った提案に惑わされないことも経験します。後半はラベルと状態で Issue を絞り込み、再現手順どおりに動かします。

今日の配属先は、**サポートデスク**。お客さんからの「困った」が、一日じゅう流れてくる場所だ。

「届いた問題は、1つずつ **Issue** になる」

Misaki がスレッドを開く。スクロールバーが、やたらと小さい。

「コメントが200ついてる Issue もある。全部読む人なんていない。大事なところだけ見つける。それが今日の仕事」

このクエストで読むのは **Issue**（英語）です。開発者が GitHub に書く、問題の報告です。

## 進め方

ファイルを読み、コマンドを実行して、ステージに答えます。

    python quest.py --stage 1
    python quest.py --stage 2
    python quest.py --stage 3

## ファイル

| ファイル | 中身 |
| --- | --- |
| `issue-214.md` | 長い Issue のスレッド（ステージ1・2） |
| `notes.py` | Issue で話題になっているツール |

`notes.py` は編集しないでください。

## Issue の読み方

Issue は会話です。見るところは次のとおりです。

| 部分 | わかること |
| --- | --- |
| タイトル（Title） | 問題を1行で表したもの |
| ラベル（Labels） | Issue の種類：`bug`、`enhancement`（新機能の案）、`question`、`duplicate` |
| 状態（State） | `open`（まだ問題が残っている）か `closed`（終わった、または却下された） |
| メンテナーのコメント | プロジェクトを管理している人の発言。いちばん重みがある |
| `+1` のコメント | 「私も」という意味。新しい情報はないので、読み飛ばしてよい |

よく見る言葉です。

| 言葉 | 意味 |
| --- | --- |
| steps to reproduce（repro steps） | 問題をもう一度起こすための手順 |
| workaround | 本当の修正が出るまでの間、問題を避けるやり方 |
| duplicate | ほかの Issue と同じ問題。その Issue は閉じられる |
| `Closing in favor of #12` | 「続きは #12 で」 |
| `fixed in 1.2.1` | 修正が入っているバージョン |

気をつけましょう。スレッドの中の人がまちがっていることもあります。誰かが書いたからといって、そのやり方が正しいとは限りません。
メンテナーが何と言っているかを確かめましょう。

## ステージ1・2：長いスレッド

`issue-214.md` を開き、上から下まで読みます。

- ステージ1は、**修正**（fix）についての問題です
- ステージ2では、**workaround** を使ってツールを動かします

## ステージ3：正しい Issue を探す

`issues/` のファイルを開きます。次の3つを全部満たす Issue を探してください。

1. `open` である
2. `bug` のラベルがついている
3. `duplicate` のラベルが**ついていない**

その Issue の **Steps to reproduce** のとおりに操作して、エラーを読みます。エラーの中にコードが入っています。

## 環境変数の設定のしかた

環境変数は、プログラムが読める設定です。
下の `NAME` と `value` はただの例です。本当の名前と値を使ってください。

ターミナルで次のように入力します。

    export NAME=value

ターミナルを閉じるまで有効です。

## 困ったとき

**ツールがエラーを表示する**

それで正常です。このクエストでは、エラーも手がかりの一部です。読みましょう。
