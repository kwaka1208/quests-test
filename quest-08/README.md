# Quest 8: The Bug Report

> **このクエストのねらい**
>
> バグ報告の4つの要素（再現手順・期待・実際・環境）を英語で書きます。書いた手順で本当にバグが再現できるかを確かめるところまでが課題です。

サポートデスクの朝。Misaki が、1件の報告を画面に出した。本文は、たった1行。

**"It doesn't work."**（動きません）

「こういうのが、毎日10件は来る」Misaki は肩をすくめた。「何が起きたのか見えなければ、直しようがない。逆に、いいバグ報告なら、1分でバグが見える」

見える報告と、見えない報告。その差は、書き方にあるらしい。

前のクエストでは Issue を**読み**ました。このクエストでは、Issue を英語で**書き**ます。

## 進め方

`tip.py` のバグを見つけ、`issue.md` にバグ報告を書いたら、チェックします。

    python check.py --stage 1

ステージの課題に合格すると、チェッカーが単語を1つ表示します。その単語で、同じステージに答えます。

    python quest.py --stage 1

ステージは2つあります。順番に進めてください。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `tip.py` | チップの割り勘ツール。バグがある |
| `issue.md` | あなたのバグ報告。**このファイルを編集します** |
| `check.py` | 報告をチェックし、単語を表示する |

`tip.py`・`check.py` は編集しないでください。

## バグ報告の4つの部分

よい報告は、4つの問いに答えます（見出しと中身は英語で書きます）。例は、別のツール `todo.py` のバグ報告です。

| 見出し | 問い | 例 |
| --- | --- | --- |
| Title | 問題を1行で言うと？ | `Crash when the task name is empty` |
| Steps to reproduce | 何をすればバグが見える？ | `1. Open a terminal.` `2. Run python todo.py add ""` |
| Expected | 本当はどうなるべき？ | `The tool says that the name is empty.` |
| Actual | 実際には何が起きる？ | `IndexError: string index out of range` |
| Environment | どこで起きた？ | `Python 3.12, Linux (Codespaces)` |

コツ：

- 手順は**番号つきのリスト**で書きます。コマンドは `python todo.py add ""` のようにバッククォートで囲みます
- エラーの行は、本物を写します。**記憶で打ち直してはいけません。** Python のバージョンによって、少しずつ言葉が違います
- 1つの報告には、1つのバグだけを書きます

比べてみましょう。

| よくない | よい |
| --- | --- |
| `It doesn't work.` | `Crash when the task name is empty` |
| `I ran it and got an error.` | `Run python todo.py add "". I see IndexError.` |

## ステージ1：報告を埋める

`tip.py` を動かして、どんなときに失敗するかを調べます。まず、ふつうの使い方を試します。

    python tip.py 50 2

それから、数をいろいろ変えて試しましょう。大きな数、小さな数、ありえない数…。
このクエストで報告するのは、**エラーで止まる**バグです（Traceback が出て止まる入力を探します）。
おかしな結果が出るのにエラーで止まらない入力を見つけたら、それもバグです。メモしておき、班の人に話してみましょう。

それから `issue.md` を開きます。タイトルを書き、`TODO` をすべて置き換えてください。

    python check.py --stage 1

## ステージ2：再現しやすくする

報告をもっとよくします。チェッカーは、あなたが書いたコマンドを実際に動かして、本当にバグが起きるかを確かめます。

- タイトルには、何が起きるかを書く（4〜10語くらい）
- 手順は番号つきのリストで、2つ以上。コマンドはバッククォートで囲む
- **Actual** には、実際のエラーの最後の行を書く
- **Environment** には、Python のバージョンと OS を書く。
  バージョンは `python --version` で確かめられます。Codespaces の OS は Linux です

      python check.py --stage 2

## 困ったとき

**チェッカーが「`…` を実行しましたが、エラーで止まりませんでした。」と言う**

書いたコマンドでは、バグが起きていません。自分で実行して、結果を見てみましょう。
