# Quest 21: The Postmortem Room

> **このクエストのねらい**
>
> 開発者が書く長めの文章（ポストモーテムと技術記事）を読みます。ポストモーテムでは、時系列・根本原因・再発防止策を読み分けます。技術記事では、TL;DR と、選ばなかった案とその理由を読み取ります。第15回の発表の準備にもなります。

リリースの翌朝。チームは v2.0 を本番のサーバーに載せた。

そこから35分間、誰もランチを注文できなくなった。

昼前には復旧した。Daiki は休む間もなく、**ポストモーテム**（障害の振り返りの記録）を書いた。

「これは、犯人探しじゃないよ」Misaki が言う。「**なぜ**起きたのか。**次はどう防ぐ**のか。その記録。読んでみて。リリースそのものより、たぶん学べることが多い」

Haruto も **devlog**（開発日誌）を書いていた。v2.0 で下した、ある設計の判断についての記事だ。

このクエストで読むのは **ポストモーテム** と **devlog**（英語）です。

## 進め方

2つの記事を読みます。ステージ3では、`receipt.py` を直して実行します。

それから、ステージに答えます。

    python quest.py --stage 1
    python quest.py --stage 2
    python quest.py --stage 3

## ポストモーテムの読み方

| 節 | わかること |
| --- | --- |
| Summary | 何が起きたかを2〜3文で。最初に読む |
| Impact | 誰が、どれくらいの時間困ったか |
| Timeline | 1分ごとの出来事 |
| Root cause | 本当の原因 |
| Action items | チームがこれから何をするか、誰がするか（Owner）、どこまで進んだか（Status） |

よく見る言葉です。

| 言葉 | 意味 |
| --- | --- |
| blameless | 人を責めない。仕組みを直す |
| root cause | 問題のいちばん底にある、本当の原因 |
| owner | その作業をする人（担当者） |
| TBD | To be decided。まだ決まっていない |
| deploy | 新しいバージョンをサーバーに載せること |

## devlog の読み方

devlog（developer's log）は、開発者が書く短い記事です。

- **TL;DR**（"too long; didn't read"：長すぎて読んでない人へ）は、いちばん上にある短い要約です。最初に読みましょう
- チームが検討した**選択肢**と、どれかを選んでほかを選ばなかった**理由**を探します。
  **because**、**so**、**but**、**trade-off**（何かを得るために何かをあきらめること）といった言葉が、理由の目印です
