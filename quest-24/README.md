# Quest 24: The Spec Writer

> **このクエストのねらい**
>
> 仕様書を英語で書きます。チームの決めごとを、番号付きのルールにし、MUST・MUST NOT・SHOULD・MAY を1つずつ使い分けます。例のファイルに出てくる項目はすべてルールにします。

最後のクエストだ。

3か月前、受付の貼り紙の前で固まっていた。README を読むのが、やっとだった。

そして今日。Haruto が持ってきたのは、これまででいちばん大きな仕事だった。

「キッチンも、ランチアプリも、サポートデスクも、新しいポイントカードのファイルを読むことになる。これが会議のメモ。仕様書にまとめてくれないか」

少し間をおいて、Haruto は続けた。

「言葉を決めるのは、今度はきみだ」

前のクエストでは、仕様書を**読み**ました。このクエストでは、仕様書を英語で**書き**ます。

## 進め方

`notes.md` と、`examples/` の例を読みます。`SPEC.md` に仕様書を書いたら、チェックします。

    python check.py --stage 1

ステージの課題に合格すると、チェッカーが単語を1つ表示します。その単語で、同じステージに答えます。

    python quest.py --stage 1

ステージは2つあります。順番に進めてください。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `notes.md` | チームが決めたこと |
| `examples/` | チームが作った、例のファイルが2つ |
| `SPEC.md` | 仕様書。**このファイルを編集します** |
| `check.py` | 仕様書をチェックし、単語を表示する |

## 仕様書の書き方

    # Points Card File 1.0

    ## Keywords

    The keywords MUST, MUST NOT, SHOULD and MAY in this spec are used as described in RFC 2119.

    ## Rules

    1. The file MUST be JSON.
    2. `version` MUST be the number `1`.
    3. ...

    ## Example

    ```json
    { ... }
    ```

- **1つの決まりに、キーワードは1つ。** キーワードが2つ要るなら、決まりを2つに分けます
- キーワードは**大文字**で書きます：`must` ではなく `MUST`
- キーワードはよく考えて選びます。メモの言葉を見ましょう

| メモの言葉 | キーワード |
| --- | --- |
| "always"、"is"、"has" | MUST |
| "never"、"can never" | MUST NOT |
| "it is better to" | SHOULD |
| "if you want"、"can also" | MAY |

- 例にある**すべてのフィールド**について、決まりを書きます
- 例は、あなた自身の決まりに従っている必要があります

## ステージ1：形

仕様書の名前、`## Keywords` の節（RFC 2119 のこと）、5つ以上の番号つきの決まりを書きます。
どの決まりにも、キーワードがちょうど1つ、大文字で入っているようにします。

    python check.py --stage 1

## ステージ2：決まったことを全部

`notes.md` で決まったことを**全部**、決まりにします。例にあるフィールドには、どれも決まりが必要です。
それから、`## Example` に `json` のコードブロックで例のファイルを1つ足します。

    python check.py --stage 2

## 困ったとき

**「キーワードはちょうど1つにしてください。いまは 2 個あります」と出る**

決まりを2つに分けます。たとえば "`points` MUST be a whole number. It MUST NOT be negative." は、
2つの決まりにします。

**「キーワードは MUST のように大文字で書いてください」と出る**

`must` ではなく `MUST` と書きます。仕様書では、小文字はただのふつうの英語で、どれくらい強い意味なのかが読む人に伝わりません。
